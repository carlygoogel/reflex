Introduction

Reflex is a System Zero model: a decision model that lives in the data path. You send a state and typed questions; an FPGA answers in a fixed number of clock cycles, on a stream or a pin instead of a socket.

Most machine decisions today are made by sending data to a processor and waiting. The processor schedules the work, runs a model, serialises a result, and sends it back. Every step adds latency, and none of it is the same twice. For a decision per request that is fine. For a decision per packet, per frame, per tick or per sample it is not an option at all.

Reflex compiles each question into its own circuit on a field-programmable gate array. The state streams through a tokeniser and a quantised encoder at one token per clock; every question's head reads the same context vector and all of them finish in the same cycle. There is no scheduler, no cache, no garbage collector and no neighbour's traffic. The answer carries the cycle count it took, and that count is identical next time.

What "cycle" means hereA cycle is one tick of the FPGA's hardware clock. At 250 MHz a tick lasts 4 nanoseconds, so 250 cycles is one microsecond. On every tick, every part of the Reflex circuit does useful work at the same time: the tokeniser reads a byte, the encoder takes a token, and the question heads read their inputs. A CPU running a model works differently. It spends much of its time on things that are not your answer: waiting for the operating system to schedule it, missing cache, copying buffers, and waiting on the network. When these docs give a decision time in cycles, the count covers the decision and nothing else.

Read this firstReflex is an open design, not a shipped product. Latency figures in these docs are targets derived from the architecture, not measurements. The Project status page says exactly what exists, the Milestones track is how targets become measurements, and the M0 emulator runs on a laptop today with the whole request shape and a modelled cycle count. If you are here to build something fast for your own problem, start with Designing for the fabric and the Blueprints.

Any mix of question types goes in one request. Each question has its own slot in the fabric, so adding a question adds a circuit, not time: 1 question and 256 questions finish in the same cycle.

Atomic questions, composed in code

One rule governs everything on the fabric. Each question should ask one well-scoped thing that a knowledgeable person could judge in a few seconds. If a judgement needs several factors, ask each factor as its own question and combine them in your code. On Reflex that combination is free: every factor is a slot, all slots finish together, and your weighting lives in a coefficient you can change without resynthesising anything.

System Zero

A System Zero model makes structured, cycle-deterministic decisions that software and hardware can act on directly. Reflex is the first one.

A System Zero model evaluates a state and returns typed answers with probabilities. It never generates text. Beyond that contract it makes two guarantees that only a fixed circuit can make:

  • Bounded latency. Every answer carries the cycle count that produced it, and that count does not change between requests to the same bitstream.
  • Hardware-addressable answers. An answer can be read from a register, pushed on an AXI4-Stream, or asserted on a pin, as well as returned over HTTP.

Reflex understands natural-language input and never writes replies, code, or explanations. You define the answer space through question types, and the fabric is laid out to answer exactly those.

Why "zero"

Kahneman's System 1 is fast, intuitive judgement, and System 2 is slow deliberation. System Zero is the layer beneath both: the reflex that fires before judgement is conscious. The name is a reminder of what these models are for. They are not for reasoning. They are for the decisions you need in the time it takes a packet to cross a switch.

Fast judgements inside a larger workflow

The workflow is the same on a laptop and on a board. Build a state, ask independent atomic questions together, combine them with deterministic checks in code, and route for action or review. Reflex adds a fourth step for hardware builders: wire the answer. A Gate question can drive an interrupt, a valid strobe or a GPIO directly, without the processor in the loop.

Call a System Zero model through a client SDK, POST /v1/systemzero in the HTTP API, or the on-board register file described in hardware examples. The model field selects the bitstream.

Why the fabric is faster

A decision model is fast when it refuses to generate text. Reflex is faster because it refuses to be scheduled. Everything below is a standard FPGA principle applied to a decision model.

1. Spatial computation

A CPU or GPU time-slices a fixed set of arithmetic units across a stream of instructions. An FPGA lays out a dedicated circuit for every operation and runs them all at once. Reflex turns each question into its own head circuit, so 256 questions are 256 circuits, not 256 passes.

2. Initiation interval of one

A pipelined circuit accepts a new input every II cycles. For a pipeline with latency L processing N inputs the total cycle count is L + II·N. Reflex's encoder and heads close at II = 1, so throughput equals the clock rate no matter how deep the pipeline is, and the first answer is still only L cycles away.

3. Streaming dataflow

The tokeniser, encoder and heads are separate processing elements joined by FIFOs. Each runs as soon as its input arrives; no stage waits for a whole request to be buffered. Intermediate activations never leave the chip.

4. On-chip memory locality

The state buffer, token embeddings and every head's criteria live in LSRAM and µSRAM blocks spread through the fabric. Every operand is one cycle away. External DDR is used only to load a bitstream.

5. Fixed-point, mixed precision

Weights are trained quantisation-aware and run as INT8 and INT4 dot products in the 18×18 math blocks' DOTP mode. Lower precision is what lets a whole encoder fit on a mid-range part: it halves math-block and memory use per step down in width, and the training loop absorbs most of the accuracy cost. Quantisation and pruning before synthesis, then an equivalence test of the hardware model against the software model, is the standard deployment path for inline inference on FPGAs and it is Reflex's too.

6. Deterministic latency

No OS, no scheduler, no cache misses, no garbage collection. A fixed circuit at a fixed clock takes a fixed number of cycles. That is why FPGAs sit in the data path of packet filters and market-data handlers: the decision is made as the data passes through, with no software loop, kernel crossing or model server in between. Reflex reports its cycle count on every answer so you can build the same guarantees.

7. Cross-layer pipelining

Encoder layers run concurrently on successive tokens instead of one layer at a time, so the latency of the stack is its depth, not the sum of its layers. Reflex's encoder is built this way, and its heads are built the same way: every slot reads the same broadcast context vector and finishes together.

8. Attention on the fabric: keep the DSPs busy

Published attention accelerators converge on the same lessons. Map every multiply-accumulate to a hard DSP or math block rather than to LUT logic; split operands across many small memories so each block has a partner every cycle; tile weight matrices to fit on-chip memory. Softmax is the awkward part, because its division is LUT-bound and sets the real limit on how many heads run in parallel. Reflex's heads use a shared fixed-point exponent table and a reciprocal step so the softmax cost is paid once per slot rather than per option.

9. Reconfigurability with decoupling

A new bitstream re-targets the same silicon. Partial reconfiguration rewrites one floorplanned partition while the static region keeps running. Done properly it needs decouplers on every AXI-Stream port of the partition, so the module cannot emit garbage or accept input while it is being rewritten, and a local reset, because the global reset does not fire after a partial load. Reflex's slot partitions are built with both, which is what lets you change a question in production without a cold start.

10. Timing closure as a design loop

reflex synth runs synthesis, place-and-route and static timing analysis, then retimes registers until the design closes at the requested clock. The clock it closed at is what the response reports as clock_mhz.

FPGA primer

What a field-programmable gate array is, what is inside one, and the vocabulary the rest of these docs use.

What an FPGA is

An FPGA is a sea of prefabricated logic resources plus a programmable routing network. Loading a bitstream sets every routing switch and every truth-table bit, turning the generic fabric into one specific circuit. Change the bitstream and the same chip becomes a different circuit. Nothing is interpreted at run time; the circuit simply exists.

  • Logic element (LE). A small look-up table plus a D flip-flop. PolarFire uses a 4-input LUT and DFF per LE; AMD and Intel parts commonly use 6-input LUTs. A K-input LUT is a 2K-bit memory that implements any Boolean function of K variables.
  • Logic cluster / CLB. A group of LEs (12 per cluster on PolarFire) joined by a local crossbar, with dedicated carry chains for fast adders and counters.
  • Routing fabric. Horizontal and vertical wire channels joined by switch boxes and connection boxes. Routing takes most of the die area and is usually what limits clock frequency. Modern fabrics use uni-directional wires and a mix of short local tracks and long-haul tracks, so a design that keeps its connections local closes at a higher clock.
  • Math blocks. Hard 18×18 multiply-accumulate units. PolarFire's run in Normal, DOTP (two 9×9 dot products summed) and SIMD modes, cascade into wide multipliers and systolic FIR chains, and carry pipeline registers on every port.
  • Embedded memory. LSRAM (20 Kb, dual-port) and µSRAM (768-bit, 64×12, three-port) blocks spread in rows through the fabric; µPROM for constants; sNVM for keys and secure data.
  • Interface logic. Each LSRAM and math block has 36 interface LEs, each µSRAM 12. Unused interface logic is ordinary user logic.
  • I/O. GPIO and high-speed banks, 12.7 Gbps SerDes transceivers, PCIe Gen2, DDR controllers. PolarFire SoC adds a five-core 64-bit RISC-V subsystem (SiFive U54-MC) on the same die, which is what Reflex's on-board driver runs on.

  • HDL (Verilog/VHDL) describes the circuit directly. HLS compiles C/C++ into RTL, with pragmas such as PIPELINE II=1, DATAFLOW, UNROLL and ARRAY_PARTITION steering the result.
  • Standard interfaces. AXI4-Stream (valid/ready handshake for data), AXI4-Lite (register maps), AXI4 memory-mapped (DMA). Reflex cores expose all three.
  • Timing closure. The loop of retiming and re-placing until every path meets the clock. Designs on current mid-range parts commonly close between 200 and 500 MHz.
  • Clock domains. Signals crossing between clocks need synchronisers; Microchip publishes metastability characterisation for its parts. Reflex keeps the whole decision path in one clock domain and crosses only at the AXI boundary.
  • Toolchains. Libero SoC and SmartDesign for Microchip; Vivado and Vitis for AMD. reflex synth drives whichever one your target needs.

Partial reconfiguration

A design is split into a static region and one or more reconfigurable partitions, each with its own floorplan area. Synthesis produces one full bitstream plus a partial bitstream per partition module. Loading a partial bitstream rewrites that partition while the static region keeps running. Three rules make it safe:

  • Put a decoupler on every AXI-Stream port of the partition. During the rewrite the partition can emit nonsense and accept data it should not; the decoupler isolates it.
  • Give the partition a local reset. The device-wide reset fires on a full configuration but not after a partial one.
  • Register the partition's inputs and outputs, and make the static region work for every combination of modules, including an empty partition.

Reflex's slot partitions follow all three, which is what makes a live question swap possible.

Inline inference: how models get into the data path

The pattern that packet filters and SmartNICs use is the template for Reflex. A model is trained in a normal framework, then quantised and pruned until it fits the fabric budget, then converted to RTL by a tool (hls4ml, a vendor AI suite, or hand-written HDL), then checked for equivalence against the software model on a held-out set, then placed inline with the existing hardware pipeline, so the decision is made as the data passes through. There is no software loop, no kernel crossing and no model server in the path. Every page in the Milestones track is one step of that workflow.

Attention on an FPGA

Transformer attention is matrix multiplication followed by softmax followed by another matrix multiplication. The multiplications map well: tile the weight matrices to on-chip memory, assign each multiply-accumulate to a hard DSP or math block, and spread operands across many small RAMs so every block has an operand every cycle. The softmax does not map well: its exponent and division are implemented in LUTs, and in practice the division is what bounds how many heads run in parallel. Sequence length and embedding width both cut throughput, which is why Reflex's encoder is narrow and its state buffer is a hard limit rather than a soft one. Head count, width and sequence length can be runtime parameters, read from registers, without resynthesis; tile size cannot.

Concepts

State

What state is, how Reflex ingests it, and why its size is the only thing that changes your cycle count.

State is the content every question in a request refers to. Reflex accepts three shapes: a string, a JSON object, or an array of text values. It adds one more: raw bytes on a stream, for Pulse questions.

{
  "state": {
    "subject": "Duplicate charge",
    "message": "I was charged twice for my subscription this month. Please refund the extra charge.",
    "account": { "plan": "pro", "tenure_months": 14, "open_tickets": 0 }
  }
}

How state becomes cycles

The state is tokenised once into an LSRAM-backed buffer and streamed through the encoder at one token per cycle. The encoder's latency is fixed; the only variable term is the token count. In the cycle model (constants are architecture estimates until M2 replaces them with measurements):

cycles = 64 (tokenise + load)  +  tokens × 1 (encoder, II=1)  +  96 (encoder drain)  +  28 (heads, all slots in parallel)

  256-token state  →  444 cycles  →  1.78 µs at 250 MHz
  512-token state  →  700 cycles  →  2.80 µs
 2048-token state  → 2236 cycles  →  8.94 µs

Questions do not appear in that formula. A request with 1 question and a request with 256 questions against the same state take the same number of cycles, because the heads are separate circuits that read the same encoder output.

Long contextReflex has no long-context header. Its state buffer is physical memory. If your state is larger than the buffer, chunk it in code and ask the same questions of each chunk; the windowed-state pattern shows how, and because chunks are independent they pipeline back to back at II = 1.

Structuring state well

  • Put the content the questions are about first. The encoder sees tokens in order, and early tokens are in the buffer longest.
  • Name fields. A JSON object with subject and message keys gives the heads more to anchor on than a bare concatenation.
  • Keep reference material (policy, rubric) in the question's criteria, not in the state, unless it changes per request. Criteria are compiled into the slot's µSRAM at synthesis time and cost zero tokens at run time.

Primitives (Questions)

The Reflex question types, the typed answers they return, how to choose between them, and how to ask several at once.

Choice

Select one option from a defined set. The answer includes the selected option, a probability for each option, and confidence. Criteria accept a string, object, or array per option.

"tone": {
  "type": "choice",
  "instructions": "What is the tone of this message?",
  "criteria": {
    "angry":   "An upset or hostile message",
    "calm":    "A neutral or polite message",
    "excited": "An enthusiastic or eager message"
  }
}
// answer
"tone": { "type": "choice", "choice": "calm", "confidence": 0.7,
          "probabilities": { "angry": 0.15, "calm": 0.80, "excited": 0.05 } }

Score

Rate the state against ordered, descriptive levels. The answer is the expected score (probability-weighted average of level indices), a probability per level, the legend, and confidence.

"urgency": { "type": "score", "instructions": "How urgent is this message?",
             "criteria": ["Can wait", "Needs attention this week", "Needs attention today"] }
// answer
"urgency": { "type": "score", "score": 1.7, "confidence": 0.55,
             "legend": { "0": "Can wait", "1": "Needs attention this week", "2": "Needs attention today" },
             "probabilities": { "0": 0.1, "1": 0.1, "2": 0.8 } }

Noul

Evaluate a yes/no question or statement and return the probability that it is true. Optional criteria with true and false descriptions sharpen the boundary.

"billing": { "type": "noul", "instructions": "Is this message about billing?" }
// answer
"billing": { "type": "noul", "noul": 0.98 }

Box

Locate what the instructions describe in an image asset. Returns four normalised edges and confidence. Box questions need an image-capable bitstream (reflex-vision) and the Reflex-Danger-Zone-Images: true header, so image handling is an explicit opt-in.

Pulse new

A Pulse is a Noul evaluated on every window of a streaming state. Where a Noul answers once per request, a Pulse answers once per window, and the windows are pipelined back to back. Use it for audio, sensor, log and packet streams where the question is the same but the state never stops.

"speech": {
  "type": "pulse",
  "instructions": "This window contains human speech",
  "window": { "bytes": 640, "stride": 320 }   // 20 ms of 16 kHz PCM, 50% overlap
}
// answer (request mode: windows resolved from the state bytes)
"speech": { "type": "pulse", "pulse": [0.02, 0.05, 0.91, 0.97, 0.96, 0.40],
            "window": { "bytes": 640, "stride": 320 }, "windows": 6 }
// in stream mode the same answer arrives one value per window on the output stream

In hosted request mode you send the whole byte array as the state and get the whole array of probabilities back. In stream mode, and on a board, each window's probability leaves the fabric a fixed number of cycles after that window's last byte arrives.

Gate new · hardware

A Gate wraps a Noul with a threshold and a physical output. When the probability crosses the threshold the fabric asserts a signal: an interrupt line, an AXI4-Stream valid, or a GPIO you name in configuration. The processor does not have to read anything for the signal to fire.

"stop": {
  "type": "gate",
  "instructions": "The operator said stop, halt, or emergency",
  "threshold": 0.85,
  "hysteresis": 0.10,          // de-assert below 0.75

Asking several at once

Put any number of questions in one request, up to the slot count. They evaluate in parallel and in isolation against the same state. Adding a question does not add cycles and does not change the other answers. Separate silicon per question is what rules out context rot between questions.

Concepts

Confidence & timing

Reflex reports certainty as a calibrated distribution on every answer, and adds a second axis no scheduled model can: how long the answer took, to the cycle.

Confidence

Every Choice and Score answer carries probabilities and a derived confidence from 0 to 1. The formulas are below, computed in fabric by a small fixed-point block in each head:

  • Noul: no separate confidence; |2p − 1| if you want one.
  • Choice: (p_max − 1/n) / (1 − 1/n). Even split is 0, certainty is 1.
  • Score: max(0, 1 − spread / MAD_unif), where spread is the probability-weighted distance in levels from the most likely level. Probability on a neighbouring level costs less than probability far away.

Confidence is computed in Q1.15 fixed point, which resolves to 1/32768. The M1 pass condition includes checking the fixed-point head against the floating-point one, so the actual rounding error is a number you measure, not one these docs assert.

Three paths

Divide confidence into ranges and give each a behaviour. High: act. Medium: act with a check. Low: do not act; route to a person or a reasoning model. Where the boundaries sit depends on the stakes, and different actions in the same system should gate at different levels.

action = r.answers["action"]
if action.confidence < 0.5:
    route_to_human(msg)                      # model is unsure; don't guess
elif action.choice == "check_balance":
    show_balance(account_id)                 # low stakes, recoverable
elif action.choice == "approve_transfer":
    if action.confidence > 0.9: confirm_then_execute(account_id)
    else:                       ask_user_to_confirm(account_id)

Timing

Every response includes a timing block. It is not an estimate. A hardware counter starts when the first byte of the state enters the FPGA and stops when the last question's answer is written. It counts clock cycles, and at 250 MHz each cycle is 4 nanoseconds.

Every one of those cycles is spent computing your answer. None is spent waiting in a queue, crossing into an operating system, fetching from a cache, or making a network hop. That is why cycles times the clock period is the whole decision time on the board, and why the count does not change between runs.

"timing": {
  "cycles": 212,
  "clock_mhz": 250,
  "latency_ns": 848,
  "deterministic": true,
  "bitstream": "reflex-1.0.0+mpfs250t.a91c"
}

deterministic is true when the request was served by a single fabric pass. It is false only when the hosted service had to chunk a state larger than the buffer, in which case cycles is the sum across chunks and may vary by one pipeline drain between runs.

Timing as a design input

Because the cycle count is fixed per bitstream, you can budget it like any other hardware latency. The reflex synth report prints the worst-case cycle count for your configured buffer size, and the SDKs expose it before any request is sent:

budget = client.bitstream_info().worst_case_cycles   # 2236 for a 2048-token buffer
assert budget / 250e6 < 10e-6                        # fits a 10 µs control-loop tick

① Tokeniser

A byte-pair-encoding trie stored in LSRAM walks one input byte per cycle and emits token ids into the state buffer. The vocabulary is part of the bitstream. JSON states are flattened to a canonical key-value byte string by the SDK before they are sent, so the tokeniser never has to parse.

② Encoder

The encoder is a transformer-style stack mapped onto a systolic array of 18×18 math blocks. Weights are quantised per parameter at training time and packed into DOTP-mode operands, two INT8 products per block per cycle. Activations flow between layers through FIFOs, so layer k+1 starts on token t while layer k is still on token t+1 (cross-layer pipelining). The whole stack closes at II = 1, so a token enters every cycle and a context vector leaves every cycle after the fill latency.

Reflex's weights are its own. They are trained with a calibrated-decision objective under a quantisation-aware schedule, against the slot architecture below. They are not a server model's weights run on an FPGA.

③ Head slots

Each question occupies a slot. A slot is a small classification head with its criteria embeddings in µSRAM and a fixed-point softmax, expected-value and confidence block. Slots read the shared context vectors in parallel through a broadcast bus and finish together, 28 cycles after the encoder drains.

The encoder's own footprint is unknown until M2; the design intent is that encoder plus 64 mixed slots fit an MPFS250T with room left for your own logic. reflex synth prints the real fit for your configuration.

④ Result file and outputs

Results land in a register file readable over AXI4-Lite and, optionally, are pushed as one packet per request on an AXI4-Stream output. Gate slots additionally drive the pin or interrupt named in configuration. A free-running cycle counter is latched at the first input beat and the last head write; the difference is what timing.cycles reports.

Hosted deployment

The hosted API fronts a pool of cards running the same bitstream. A request is routed to a card, DMA'd in, evaluated in one pass, and DMA'd out. Host-side overhead (network, PCIe, DMA) is reported separately in the Reflex-Host-Latency-us response header so you can see exactly how much of your round trip was the fabric.

Reconfiguration

Slot regions are floorplanned as partial-reconfiguration partitions. Changing a question's criteria rewrites µSRAM contents without reconfiguring anything. Changing a question's type reconfigures only that slot's partition while the rest of the core keeps serving. Changing the encoder or buffer size is a full bitstream and a cold start.

Engineer's guide

Designing for the fabric

Step 1. Find the decision in the data path

A hosted model sits beside your system: your code calls it, waits, and branches. Reflex sits in your system's data path, where the data already flows: a packet stream, a sensor bus, a log pipe, a market feed, a microphone. Draw your pipeline and mark the point where a judgement is made and something downstream changes because of it. That point is where the core goes. If there is no such point, if the judgement is made by a person reading a report, Reflex has nothing to accelerate.

AskWhere in the flow is the decision taken, and what is the next thing that happens because of it?

Step 2. Make the state a window

A fabric core has a fixed input buffer. Decide what one unit of state is: one packet, one message, one 20 ms audio frame, one log line with its previous five, one order-book delta with the last hundred. The window must fit the buffer and must contain everything the decision needs, because there is no second look. Overlap consecutive windows when events can straddle a boundary.

The payoff is that windows are independent. Independent inputs pipeline at II = 1, so the core processes one window per clock-count regardless of how many are queued, and the latency for any single window is the same.

AskWhat is the smallest window that contains the whole decision, and how often does one arrive?

Step 3. Decompose into atomic questions

This is the rule that makes the fabric work. Each question must be answerable from one window by one small head. Not "is this packet malicious" but five Nouls: unusual port, known-bad pattern in payload, rate anomaly in the window, protocol violation, matches an active rule set. Not "how good is this lead" but three Scores. Combine in code, or in a Gate.

Decomposed questions are also what makes the slot architecture cheap. A broad question needs a big head; five narrow ones need five small heads that all finish in the same cycle.

AskCould a knowledgeable person answer each question in a few seconds from the window alone?

Step 4. Decide what acts on the answer

Three options, in increasing speed and decreasing flexibility:

  • Your code reads the register file. Full flexibility; adds the processor's read latency and whatever your code does.
  • The answer leaves on a stream. One result packet per window on AXI4-Stream, consumed by the next hardware block. No processor in the loop.
  • A Gate drives a signal. Threshold and hysteresis in fabric, a pin or interrupt out. The decision and the action are the same cycle; the processor learns about it afterwards.

Use the fastest option that your veto path can tolerate. The act-then-explain pattern is the Gate with a software veto behind it.

AskIf this answer is wrong, how is it undone, and by what?

Step 5. Set the latency budget before you build

Write down the deadline in the units of the data: cycles of a control loop, inter-arrival time of packets, frame period. Convert the core's worst-case cycle count to time at the closed clock and compare. On the emulator this is a modelled number; after M2 it is a measured one. If it does not fit, the levers are, in order: a shorter window, fewer encoder layers, lower precision, a bigger part. Adding questions is never a lever, because questions do not cost cycles.

AskWhat is the deadline, where does it come from, and what fraction of it can the decision take?

Step 6. Plan for change

Criteria change without reconfiguration (they are µSRAM contents). Question types change with a partial reconfiguration of one slot. Window size, encoder depth and buffer depth change with a full bitstream. Put the things most likely to change in the layer that is cheapest to change: thresholds and criteria in registers, question types in slots, the encoder last.

AskWhich of these will change next quarter, and which layer is it in?

What "faster" means in practice

Not a smaller number on the same benchmark. A hosted model is a request-response service; Reflex is a component in a data path. The problems Reflex is for are the ones a hosted model cannot be put in at all: decisions per packet, per frame, per tick, per sample, where the deadline is set by hardware and the volume makes a round trip per decision impossible. For those, "better" means the decision happens where the data is, in a fixed number of cycles, with a question-and-answer contract your code can branch on. The Blueprints page is a list of such problems with the window, questions and actuation worked out.

Speculative fan-out

On the fabric, extra questions are free up to the slot count: each one is a circuit that was going to be idle anyway. Ask every question that might matter and let code pick what to use. The one cost is slots, which you size in configuration.

Confidence-gated routing

The answer says what; confidence says whether to act. See Confidence & timing.

Composite scoring

Break a complex judgement into atomic Scores, combine with weights in code. When priorities change, change a coefficient; nothing is resynthesised.

w = {"market": 0.4, "feasibility": 0.35, "differentiation": 0.25}
total = sum(w[k] * r.scores[k].score / 2 for k in w)   # each Score has 3 levels, 0–2

Intent routing

One Choice classifies an incoming request; code routes it to deterministic logic, a specialist LLM, or a person. Reflex makes the router cheap enough to put in front of every packet, not just every conversation.

Windowed state

When a state exceeds the buffer, split it into overlapping windows of state_tokens and send each as its own request with the same questions. Chunks are independent so they pipeline at II = 1; the SDK's windowed() helper does the split and merges Noul answers with max, Score with mean, and Choice by summed probabilities.

r = client.windowed(state=long_contract, tokens=2048, overlap=128,
                    questions={"has_termination": Noul(instructions="A clause lets either party end the agreement early")},
                    merge="max")
print(r.nouls["has_termination"].noul, r.timing.cycles)   # 0.97  11180 (5 chunks, deterministic per chunk)

Latency budgeting

Read worst_case_cycles from the bitstream info at start-up, convert to time at the closed clock, and refuse to deploy if it exceeds the control loop's deadline. The cycle count cannot get worse at run time, so a check at start-up is a guarantee, not a hope.

Act-then-explain

A Gate asserts a pin as soon as its Noul crosses threshold. The processor reads the full answer afterwards, logs it, and can override by de-asserting. The decision is in the fabric; the explanation is in the register file. Use this wherever the cost of acting late is higher than the cost of acting on a false positive you can undo.

Blueprints

Worked decompositions for problems where a decision has to be made in the data path. Each gives the window, the atomic questions, what acts on the answer, and the deadline that sets the budget. Copy the shape; replace the words.

1. Inline packet triage on a SmartNIC

Where. After the P4 or hand-written parser, before the host DMA. Window. Parsed header fields plus the first 256 bytes of payload, flattened to a key-value byte string by the parser. Deadline. Inter-arrival time at line rate; the core must keep up or apply back-pressure.

[questions.syn_flood]   type="noul"  instructions="This flow's SYN rate in the window is anomalous for the source"
[questions.known_bad]   type="noul"  instructions="The payload prefix matches a known exploit pattern"
[questions.proto_viol]  type="noul"  instructions="Header fields violate the declared protocol"
[questions.sensitivity] type="score" instructions="How sensitive is the destination service"
                        criteria=["public", "internal", "restricted"]
[questions.drop]        type="gate"  instructions="This packet should be dropped" threshold=0.9 output="axis:drop_valid"

Acts. drop_valid feeds the packet filter's drop input directly. The host reads the full answer only for packets it receives, for logging. Why fabric. A round trip per packet is not a design option at any line rate.

2. Market-data event classification

Where. Between the feed handler and the strategy logic, both already in fabric on a tick-to-trade card. Window. The decoded message plus the last N book deltas for the symbol, kept in a ring in LSRAM. Deadline. The card's existing budget per message, which is nanoseconds to low microseconds.

[questions.sweep]     type="noul"   instructions="The window shows a sweep through multiple price levels"
[questions.spoof]     type="noul"   instructions="Large orders were placed and cancelled without trading"
[questions.regime]    type="choice" instructions="Which liquidity regime is the book in"
                      criteria={ thin="few levels, wide spread", normal="", deep="many levels, tight spread" }
[questions.halt]      type="gate"   instructions="Conditions warrant pausing quoting on this symbol"
                      threshold=0.95 hysteresis=0.2 output="axis:quote_pause"

Acts. quote_pause gates the strategy's output; regime is read by the strategy block as a parameter. Note. This is a classifier, not a risk control; it runs alongside the existing kill switch, never instead of it.

3. Voice command on a device with no cloud

Where. On the audio path, before any codec. Window. 20 ms of 16 kHz PCM, 50% overlap. Deadline. One window period; the Gate must settle before the next window completes.

[questions.speech]  type="pulse" instructions="This window contains human speech" window={ bytes=640, stride=320 }
[questions.wake]    type="pulse" instructions="The wake word was spoken"              window={ bytes=640, stride=320 }
[questions.stop]    type="gate"  instructions="The operator said stop, halt, or emergency"
                    threshold=0.85 hysteresis=0.1 output="gpio:PB4"

Acts. stop drives a relay in parallel with the hard-wired stop; wake raises an interrupt that starts the processor. Why fabric. No network, and a 20 ms frame period rules out any round trip.

4. Log and telemetry triage at ingest

Where. On the ingest card or the first hop of the pipeline, before storage. Window. One line plus its five predecessors from the same source. Deadline. Sustained ingest rate; back-pressure is acceptable, loss is not.

[questions.severity]   type="score"  instructions="Severity of the event in the last line, given the preceding lines"
                       criteria=["noise", "info", "warning", "error", "incident"]
[questions.pii]        type="noul"   instructions="The line contains a personal identifier that must be redacted"
[questions.component]  type="choice" instructions="Which subsystem emitted this" criteria={ ...your components... }
[questions.page]       type="gate"   instructions="This event should page the on-call engineer now"
                       threshold=0.92 hysteresis=0.3 output="irq:4"

Acts. severity and component go into the index as fields; pii routes the line to the redactor; page interrupts the control processor. Why fabric. Software can do this per line in a batch job afterwards. Reflex does it before the line is written, so the index never has to be rebuilt.

5. Sensor anomaly on an industrial bus

Where. Between the fieldbus controller and the PLC. Window. The last 64 samples of each of up to 16 channels, decimated to fit the buffer. Deadline. The control-loop tick.

[questions.drift]     type="noul"  instructions="A channel is drifting outside its historical band"
[questions.stuck]     type="noul"  instructions="A channel has stopped changing while others move"
[questions.severity]  type="score" instructions="How severe is the worst anomaly in the window"
                      criteria=["none", "watch", "degraded", "fault"]
[questions.trip]      type="gate"  instructions="The process should be moved to a safe state"
                      threshold=0.97 hysteresis=0.4 output="gpio:SAFE_REQ"

Acts. SAFE_REQ is an input to the safety PLC, which makes the final call. Note. The hysteresis is wide on purpose; a trip that chatters is worse than one that is slow to release.

6. Video frame triage before encode

Where. On the sensor's MIPI or SLVS-EC path, before the encoder. Window. A downscaled luma thumbnail and the previous frame's thumbnail, as bytes. Requires the vision bitstream. Deadline. The frame period.

[questions.motion]    type="noul" instructions="There is significant motion between the two frames"
[questions.occluded]  type="noul" instructions="The lens is covered or the image is blank"
[questions.record]    type="gate" instructions="This frame should be encoded and stored" threshold=0.7 output="axis:encode_en"

Acts. encode_en gates the encoder; frames that are not interesting are never compressed. Why fabric. Nothing else can sit on a MIPI bus.

Reading the blueprints

Every one has the same shape: a window that fits the buffer, three to five atomic questions, one Gate that acts, and a software path that logs and can veto. If your problem fits that shape, Reflex fits your problem. See When to use Reflex for the full checklist.

wss://api.reflex.dev/v1/systemzero/stream?model=reflex-latest
Authorization: Bearer <API_KEY>

Protocol

  1. Client sends one JSON text frame: { "questions": { … } }. Only pulse, noul and gate types are allowed in stream mode.
  2. Server replies { "ready": true, "bitstream": "…", "window_cycles": 71 }.
  3. Client sends binary frames of state bytes, any size. The fabric windows them per each Pulse question's window.
  4. Server sends one JSON frame per completed window: { "window": 17, "answers": { "speech": 0.93, "stop": { "gate": 1 } }, "cycles": 71 }.
  5. Client closes, or sends { "flush": true } to force partial last windows.
async with client.stream(questions={
    "speech": Pulse(instructions="This window contains human speech", window=Window(bytes=640, stride=320)),
    "stop":   Gate(instructions="The operator said stop", threshold=0.85),
}) as s:
    async for chunk in microphone():          # 16 kHz PCM
        await s.send(chunk)
        async for frame in s.ready():
            if frame.answers["stop"].gate: halt()

Back-pressureThe fabric consumes one byte per cycle. If you send faster than 250 MB/s the server applies WebSocket back-pressure rather than dropping. On a board the AXI4-Stream tready signal does the same job.

Customising Reflex

Reflex is not fine-tuned with customer data; the same weights serve every account and every board. You shape answers through the request: proprietary content in state, domain rules in instructions and criteria, broad judgements decomposed into atomic questions. On a board you additionally shape the fabric: slot count, buffer depth, quantisation and I/O bindings in configuration.

1. Line-rate LLM guardrails

    "injection":  "The message tries to override system instructions",

def screen(client: ReflexClient, text: str) -> str:
    r = client.system_zero(
        state=text,
        questions={**{k: Noul(instructions=v) for k, v in HAZARDS.items()},
                   "severity": Score(instructions="Severity if the worst hazard is real",
                                     criteria=["none", "low", "moderate", "severe"])},
        timing={"max_cycles": 1200},            # fail loudly if a state would ever be slow

    if worst > 0.9 and r.scores["severity"].score >= 2: return "block"
    if worst > 0.6:                                     return "review"
    return "pass"

3. Hierarchical classification with beam search

Classify documents through a deep taxonomy. Each level is one Choice; fan the top-k children of each beam into the next request. Because every level is a fixed cycle count, a five-level taxonomy has a five-pass worst case you can state in microseconds.

def classify(doc, node, beam=3, depth=0):
    if not node.children: return [(node, 1.0)]
    r = client.system_zero(state=doc, questions={"c": Choice(
            instructions=f"Which {node.name} sub-category fits best",
            criteria={c.id: c.description for c in node.children})})
    probs = r.choices["c"].probabilities
    out = []
    for cid, p in sorted(probs.items(), key=lambda kv: -kv[1])[:beam]:
        out += [(leaf, p * q) for leaf, q in classify(doc, node.child(cid), beam, depth + 1)]
    return sorted(out, key=lambda t: -t[1])[:beam]

4. HLS wrapper for a packet classifier

If your pipeline is in C++ HLS, treat the core as a stream function. The pragmas below are what keep your side at II = 1 so the core is never starved.

#include "reflex_hls.h"
#include <hls_stream.h>

void classify_packets(hls::stream<axis8_t> &pkt_in,
                      hls::stream<rfx_result_t> &res_out,
                      ap_uint<16> &gate_bits) {
#pragma HLS INTERFACE axis port=pkt_in
#pragma HLS INTERFACE axis port=res_out
#pragma HLS INTERFACE ap_none port=gate_bits
#pragma HLS DATAFLOW
    hls::stream<axis8_t> payload;
#pragma HLS STREAM variable=payload depth=64
    strip_headers(pkt_in, payload);              // your logic, PIPELINE II=1 inside
    reflex_core<16, 1024>(payload, res_out, gate_bits);   // generated; closes at II=1
}

What "target" means here

A target figure is derived from one of two things: the architecture (a pipelined encoder at II = 1 accepts one token per cycle by construction) or the device data sheet (an MPFS250T has 784 math blocks). Where a constant is a plain guess, such as the 96-cycle encoder drain, the page says so. None of them are measurements of Reflex, because Reflex has not been measured.

What you can trust today

  • The request shape: state plus named typed questions, so the drop-in lets existing decision-model client code run against the emulator unchanged.
  • The confidence formulas: documented on the Confidence page and implemented in the emulator with the fixed-point format a head would use.
  • The FPGA facts: everything in the primer is sourced.
  • The M1 recipe: QKeras and hls4ml are real, open tools that produce real RTL from a small head, and the recipe below is how trigger systems are built today.

Milestones

Four milestones, each with a pass condition you can check without trusting anyone. Finish one before starting the next; each one changes what the next should be.

M0: Software emulator runnable

Goal. Implement the full Reflex request shape in Python with real (if modest) answers and a modelled cycle count, so every downstream tool, test and SDK can be written against something that runs.

Pass condition. The quick-start ticket request returns a Choice, Score and Noul with calibrated probabilities and confidence, and the same request returns the same timing.cycles every time.

What it proves. The schema, the composition patterns and the cycle model. What it does not prove: accuracy or latency of anything in silicon.

M1: One Noul head in fabric reproducible recipe

Goal. Train a tiny quantised head on frozen context vectors from the M0 model, export it with hls4ml, synthesise to RTL, and read its latency and resource use from the tool report.

Pass condition. Vitis HLS or Libero reports II = 1 and a fixed latency for the head; the C-simulation output matches the Python head on 1,000 held-out examples to within fixed-point rounding.

What it proves. The slot concept costs what the architecture page claims, within a factor of two. It replaces the "~640 LEs, 2 math blocks" estimate with a number.

M2: Quantised encoder in fabric target

Goal. Replace the stand-in encoder with a small transformer (2–4 layers, 128–256 wide) trained quantisation-aware with calibrated-decision heads, and map it onto the math-block systolic array.

Pass condition. A 256-token state passes through the encoder at II = 1 with a fixed latency on a real board, and the heads' answers on a labelled set are within a stated margin of the floating-point model.

Why this is the hard one. Attention over the full buffer at II = 1 is quadratic in tokens; the fit on a mid-range part depends on sequence length, width and the quantisation scheme. This milestone is where the 4k-token figure on the State page gets replaced by whatever actually closes timing. Budget months, not weeks.

M3: Slot bank, result file, Gate target

Goal. N heads reading one broadcast context vector, the AXI4-Lite register file from the C SDK page, Gate threshold logic driving a fabric pin, and partial-reconfiguration partitions per slot.

Pass condition. Adding a slot does not change CYCLES; a Gate asserts a pin a fixed number of cycles after the last state byte; swapping one slot's partition does not interrupt the others.

What it proves. The headline claim: questions are circuits, not time.

Only then

Only after M2 and M3 is there a number to compare against a server-side decision model, and the benchmark method page says how to produce it so the comparison is fair.

from __future__ import annotations
import json, math
from dataclasses import dataclass, field
import numpy as np
from sentence_transformers import SentenceTransformer

# ---------- fixed point: Q1.15, the format a fabric head would write ----------
Q = 1 << 15
def q15(x: float) -> int: return int(round(max(-1.0, min(1.0, x)) * Q))
def fq15(x: int) -> float: return x / Q

# ---------- confidence formulas ----------
def choice_conf(p: list[float]) -> float:
    n = len(p); return 0.0 if n == 1 else (max(p) - 1 / n) / (1 - 1 / n)

def score_conf(p: list[float]) -> float:
    n = len(p); m = int(np.argmax(p))
    spread = sum(pi * abs(i - m) for i, pi in enumerate(p))
    even = sum(abs(i - (n - 1) / 2) for i in range(n)) / n
    return max(0.0, 1 - spread / even) if even > 0 else 1.0

# ---------- cycle model: constants are ESTIMATES until M2 replaces them ----------
@dataclass
class CycleModel:
    clock_mhz: int = 250
    load: int = 64         # tokenise + buffer fill
    per_token: int = 1     # encoder at II = 1
    drain: int = 96        # pipeline depth of the encoder stack
    heads: int = 28        # all slots, in parallel
    def cycles(self, tokens: int) -> int:
        return self.load + self.per_token * tokens + self.drain + self.heads

# ---------- stand-in encoder ----------
class Encoder:
    def __init__(self, name="sentence-transformers/all-MiniLM-L6-v2"):
        self.m = SentenceTransformer(name)
    def tokens(self, text: str) -> int:
        return len(self.m.tokenizer(text)["input_ids"])
    def embed(self, texts: list[str]) -> np.ndarray:
        return self.m.encode(texts, normalize_embeddings=True)

def softmax(x, t=0.05):
    z = np.exp((np.asarray(x) - np.max(x)) / t); return (z / z.sum()).tolist()

def flatten_state(state) -> str:
    if isinstance(state, str): return state
    return json.dumps(state, ensure_ascii=False)   # canonical, same as the SDK does

# ---------- the core ----------
class ReflexEmulator:
    def __init__(self, slots=64, state_tokens=2048, cycle_model=CycleModel()):
        self.enc, self.slots, self.state_tokens, self.cm = Encoder(), slots, state_tokens, cycle_model

    def system_zero(self, state, questions: dict) -> dict:
        if len(questions) > self.slots: raise ValueError(f"NoSlots: {len(questions)} > {self.slots}")
        text = flatten_state(state)
        ntok = self.enc.tokens(text)
        if ntok > self.state_tokens: raise ValueError(f"StateTooLarge: {ntok} > {self.state_tokens}")
        s = self.enc.embed([text])[0]
        answers = {name: self._head(s, q) for name, q in questions.items()}
        cyc = self.cm.cycles(ntok)
        return {"model": "reflex-emu-0.1", "answers": answers,
                "timing": {"cycles": cyc, "clock_mhz": self.cm.clock_mhz,
                           "latency_ns": round(cyc * 1000 / self.cm.clock_mhz),
                           "deterministic": True, "bitstream": "emulator"},
                "usage": {"input_tokens": ntok, "slots_used": len(questions)}}

    def _head(self, s, q):
        t = q["type"]; ins = q.get("instructions", "")
        if t == "choice":
            names = list(q["criteria"])
            E = self.enc.embed([f"{ins}: {names[i]}. {q['criteria'][names[i]] or ''}" for i in range(len(names))])
            p = [fq15(q15(x)) for x in softmax(E @ s)]
            return {"type": t, "choice": names[int(np.argmax(p))],
                    "confidence": fq15(q15(choice_conf(p))), "probabilities": dict(zip(names, p))}
        if t == "score":
            lv = q["criteria"]
            E = self.enc.embed([f"{ins}: {l}" for l in lv])
            p = [fq15(q15(x)) for x in softmax(E @ s)]
            return {"type": t, "score": round(sum(i * pi for i, pi in enumerate(p)), 4),
                    "confidence": fq15(q15(score_conf(p))),
                    "legend": {str(i): l for i, l in enumerate(lv)},
                    "probabilities": {str(i): pi for i, pi in enumerate(p)}}
        if t in ("noul", "gate"):
            c = q.get("criteria") or {}
            yes = c.get("true") or ins
            no  = c.get("false") or f"not the case that {ins}"
            E = self.enc.embed([yes, no])
            p = fq15(q15(softmax(E @ s)[0]))
            if t == "noul": return {"type": t, "noul": p}
            g = int(p >= q["threshold"])
            return {"type": t, "gate": g, "noul": p,
                    "asserted_at_cycle": (self.cm.load + self.cm.drain + self.cm.heads) if g else None}
        raise ValueError(f"unsupported type {t} in M0")

What to do with it

  • Write the SDKs against it. Point ReflexClient(base_url=…) at a 30-line FastAPI wrapper around system_zero and the Python and TypeScript SDK pages become real.
  • Collect training data through it. Log every request and answer; when you train real heads (M1) you want exactly this shape.
  • Replace the constants. CycleModel is the one place estimates live. M1 and M2 each overwrite a field with a measurement.
  • Calibrate the stand-in. The softmax temperature (0.05) is a guess. Fit it on a labelled set with a reliability diagram before you trust any confidence threshold, and expect to throw the stand-in away at M2.

Known limits of the stand-inCosine similarity over sentence embeddings ignores instructions beyond the words in them, does not reason about negation well, and treats a Score's levels as unordered labels. It will get the quick-start ticket right and will get subtle rubrics wrong. That is fine for M0, whose job is plumbing.

M1: One head in fabric reproducible recipe

Train a small quantised Noul head on frozen context vectors, export it to RTL with hls4ml, and read latency and resources from the synthesis report. These are open tools in production use for inline inference, and the recipe runs on a laptop up to the synthesis step.

1. Make a dataset of (context vector, label)

import numpy as np
from reflex_emu import Encoder
enc = Encoder()
texts, labels = load_your_labelled_set()        # e.g. 5k support tickets, label = is_urgent ∈ {0,1}

np.savez("urgent.npz", X=X, y=y)

2. Train a quantised head with QKeras

from qkeras import QDense, QActivation, quantized_bits, quantized_relu
from tensorflow.keras import Sequential, Input

head = Sequential([
    Input((384,)),
    QDense(32, kernel_quantizer=quantized_bits(8, 0, alpha=1), bias_quantizer=quantized_bits(8, 0, alpha=1)),
    QActivation(quantized_relu(8)),
    QDense(1,  kernel_quantizer=quantized_bits(8, 0, alpha=1), bias_quantizer=quantized_bits(8, 0, alpha=1)),
    QActivation("sigmoid"),
])
head.compile(optimizer="adam", loss="binary_crossentropy", metrics=["AUC"])
head.fit(X, y, epochs=30, batch_size=256, validation_split=0.2)
head.save("noul_head.h5")

Thirty-two hidden units and INT8 is the smallest head that keeps AUC on a typical ticket set; it is also roughly the "2 math blocks" slot the architecture page estimates. Shrink or grow it and watch the synthesis report, which is the whole point of this milestone.

3. Export to RTL with hls4ml

Extending to Choice and Score

A Choice head is the same network with n sigmoid outputs replaced by an n-way softmax; hls4ml supports Softmax with a lookup-table implementation. A Score head is a Choice head over the levels followed by the expected-value and MAD arithmetic, which is ~40 lines of fixed-point C++ you add to the generated project. The confidence formulas in reflex_emu.py are the reference for that C++.

# Drop-in for a client SDK that exposes `DecisionClient, Choice, Score, Noul`
from dataclasses import dataclass, asdict
from types import SimpleNamespace
from reflex_emu import ReflexEmulator

@dataclass
class Choice: instructions: str = ""; criteria: dict = None
@dataclass
class Score:  instructions: str = ""; criteria: list = None
@dataclass
class Noul:   instructions: str = ""; criteria: dict = None

def _q(x):
    d = {k: v for k, v in asdict(x).items() if v is not None}
    d["type"] = type(x).__name__.lower(); return d

class DecisionClient:
    def __init__(self, model="reflex-emu", backend=None): self.b = backend or ReflexEmulator()
    def __enter__(self): return self
    def __exit__(self, *a): pass
    def system_one(self, state, questions):
        r = self.b.system_zero(state, {k: _q(v) for k, v in questions.items()})
        ns = lambda d: SimpleNamespace(**d)
        A = {k: ns(v) for k, v in r["answers"].items()}
        return SimpleNamespace(
            model=r["model"], answers=A, timing=ns(r["timing"]), usage=ns(r["usage"]),
            choices={k: v for k, v in A.items() if v.type == "choice"},
            scores ={k: v for k, v in A.items() if v.type == "score"},
            nouls  ={k: v for k, v in A.items() if v.type == "noul"})

Why this matters for adoption

Every decision recipe you already run in software (guardrails, re-ranking, hierarchical classification, date extraction, memory) becomes a Reflex test case for free. Run them through the shim against the emulator to catch schema regressions, and later against a board to produce the accuracy half of the benchmark.

Differences the shim does not hide: Reflex has no long-context header (use windowed()), Box needs an image bitstream, and usage adds slots_used.

Benchmark method

How to measure the server-side decision model you use today, how to measure Reflex, and how to compare them without fooling yourself or anyone else. Run this before posting a number.

Measure your hosted service's real latency today

Whatever server-side decision model you use today is real and you can time it now. This is the only side of the comparison that currently produces a measurement. The code uses a placeholder client; substitute the SDK you use.

import time, statistics, os
from your_decision_sdk import Choice, Noul, Score, DecisionClient   # whichever hosted SDK you use

qs = {...}   # the quick-start questions
lat = []
with DecisionClient(model="<pinned version id>") as c:   # pin the version; aliases move
    for _ in range(10): c.system_one(state=ticket, questions=qs)   # warm up
    for _ in range(200):
        t0 = time.perf_counter(); c.system_one(state=ticket, questions=qs); lat.append(time.perf_counter() - t0)
print("hosted p50/p99 ms", statistics.median(lat)*1e3, sorted(lat)[197]*1e3)

Record the client's location, the state's token count (from usage.input_tokens), the model id from the response, and the time of day. Network round trip is part of this number; say so.

Measure Reflex when there is something to measure

There are three different numbers, and they are not interchangeable:

  1. Fabric cycles. From the CYCLES register or the HLS report. Multiply by the closed clock period. This is the number Reflex's design is about.
  2. Board round trip. From the processor's point of view: push state, wait for done, read answers. Includes AXI and driver overhead. Measure with reflex bench or a C loop around the SDK calls.
  3. Network round trip. Only exists once a hosted service exists. This is the only number that is like-for-like with the hosted measurement above.

Until M3, the only Reflex figure is (1) for a single head from M1, and a modelled total from the emulator. A modelled number is not a measurement and must be labelled as a model.

Comparing fairly

  • Same questions, same state, same token count on both sides.
  • Compare like with like: fabric cycles against the service's server-side time if it publishes one, otherwise network RTT against network RTT.
  • Report p50, p99 and p100 for both. Reflex's whole argument is that p100 equals p50; show it rather than assert it.
  • Report accuracy on the same labelled set alongside latency. A faster wrong answer is not a result.
  • State the hardware: part, clock, tool versions, bitstream hash, and where the hosted client ran.

M2: "a 256-token state is encoded in N cycles on part P at F MHz, with accuracy A on set S."
